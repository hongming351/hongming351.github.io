# Java 项目开发 · 专业术语速查手册

> 按主题分类。每个术语附"你项目里的实例"，方便对照复习。

---

## 一、Java 运行环境

### JDK（Java Development Kit）
Java 开发工具包。包含编译器 `javac`、运行时 `java` 及其他开发工具。**开发 Java 必须装 JDK。**

### JRE（Java Runtime Environment）
Java 运行时环境。只有 `java` 等运行组件，**没有 `javac`**。只能运行已编译的 `.class`，不能开发。

### JVM（Java Virtual Machine）
Java 虚拟机。执行 `.class` 字节码的引擎。**"一次编译，到处运行"** 靠的就是不同平台各有自己的 JVM。

### 字节码（Bytecode）
`.java` 经 `javac` 编译后生成的中间代码，存于 `.class` 文件中。JVM 能读，人类也能读（但不好读）。

```bash
javac Main.java     # .java → .class（字节码）
java Main           # JVM 加载 .class 并执行
```

### classpath（类路径）
JVM 查找 `.class` 文件和依赖 jar 的"搜索目录清单"。

```bash
java -cp out Main        # 从 out/ 目录找 Main.class
```

## 二、面向对象基础

### 类（Class）与对象（Object / Instance）
- **类**是模板，描述"有什么属性、有什么行为"
- **对象**是按模板创建出来的具体实例

```java
Student s = new Student("001", "小明", 85.5);
//    ↑对象       ↑类           ↑构造器
```

### 构造器（Constructor）
创建对象时自动调用的特殊方法，名字与类名相同，无返回值。

```java
public Student(String id, String name, double score) {
    this.id = id;
    this.name = name;
    this.score = score;
}
```

### 封装（Encapsulation）
把字段设为 `private`，只通过 `getter/setter` 访问。**目的：保护内部状态，解耦字段名。**

```java
private String name;                    // 外部不能直接改
public String getName() { return name; } // 只能通过方法读
```

### 重写（Override）
子类或本类重新实现父类/`Object` 的方法。用 `@Override` 标注。

```java
@Override
public String toString() {
    return id + " | " + name + " | " + score;
}
```

### 静态（static）
属于类而非某个对象。用 `类名.成员` 访问，不需要 `new`。

```java
static ArrayList<Student> list = new ArrayList<>();   // 所有实例共享
static void showAll() { ... }                          // 不依赖对象状态
```

### 全限定名（Fully Qualified Name）
带包名的完整类名。`App` 的全限定名可能是 `ui.App`。

```java
java -cp out ui.App     # 必须用全限定名
```

## 三、包与访问控制

### 包（Package）
组织类的命名空间，避免类名冲突。**目录结构必须与包名一致。**

```java
package service;    // 文件必须放在 src/service/ 下
```

### import
引入其他包中的类，才能在代码里直接用类名。

```java
import model.Student;
import service.StudentManager;
```

### 访问修饰符

| 修饰符 | 可见范围 |
|---|---|
| `private` | 仅本类 |
| `(默认)` | 同包 |
| `protected` | 同包 + 子类 |
| `public` | 全局 |

## 四、集合与数据结构

### List / ArrayList
- **List**：有序、可重复的集合接口
- **ArrayList**：基于数组实现的 List，查询快、增删慢

```java
List<Student> students = new ArrayList<>();
students.add(new Student(...));
students.get(0);
students.size();
```

### 遍历（Iteration）
按顺序访问集合中每个元素。

```java
for (Student s : students) { ... }              // for-each
for (int i = 0; i < students.size(); i++) { ... } // 索引
```

### 引用（Reference）
对象变量存储的是"指向对象内存的地址"，不是对象本身。**两个变量可以指向同一个对象。**

```java
Student a = list.get(0);
Student b = list.get(0);
a.setName("x");
System.out.println(b.getName());   // 输出 x，因为是同一个对象
```

### null
"空引用"，表示变量不指向任何对象。对 `null` 调用方法会抛 `NullPointerException`。

```java
Student s = findById("999");
if (s != null) { ... }   // 用前必须判空
```

## 五、字符串与比较

### `equals()` vs `==`
- `==`：比较**引用**（是否同一个对象）
- `equals()`：比较**内容**（是否字符串相同）

```java
s.getId().equals(id)    // ✅ 比较内容
s.getId() == id         // ❌ 可能为 false（不同对象）
```

### `isEmpty()`
字符串或集合是否为空。

```java
if (!name.isEmpty()) { ... }   // 用户没直接回车
```

### `split()`
按分隔符把字符串拆成数组。

```java
String[] parts = "001,小明,85.5".split(",");
// parts = ["001", "小明", "85.5"]
```

## 六、异常处理

### 异常（Exception）
程序运行时的错误。Java 用 `try-catch` 捕获，不处理会终止程序。

### 常见异常类型

| 异常 | 触发场景 |
|---|---|
| `InputMismatchException` | `Scanner.nextDouble()` 读到非数字 |
| `NumberFormatException` | `Double.parseDouble("abc")` |
| `IOException` | 文件读写失败 |
| `NullPointerException` | 对 `null` 调方法 |
| `IndexOutOfBoundsException` | 访问不存在的数组/列表下标 |

### try-catch
捕获并处理异常。

```java
try {
    double score = sc.nextDouble();
} catch (InputMismatchException e) {
    System.out.println("请输入数字");
    sc.nextLine();              // 清掉坏输入，否则死循环
}
```

### try-with-resources
自动关闭资源（`Connection`、`Reader` 等），无需手动 `close()`。

```java
try (Connection conn = DriverManager.getConnection(url)) {
    // 自动关闭 conn
}
```

## 七、文件与 IO

### 相对路径 vs 绝对路径
- **相对路径**：相对于**当前工作目录**（你执行命令的目录）
- **绝对路径**：从根目录开始的完整路径

```java
Paths.get("students.txt")                  // 相对
Paths.get("/home/user/students.txt")       // 绝对
```

### NIO（New I/O）
Java 7+ 的文件 API，位于 `java.nio.file`。比老的 `File` 类更简洁。

```java
Files.readAllLines(path);       // 读全部行
Files.write(path, lines);       // 写全部行
Files.exists(path);             // 是否存在
```

### UTF-8
一种字符编码，支持所有语言字符。**项目统一用 UTF-8，避免中文乱码。**

```xml
<project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
```

### 工作目录（Working Directory）
程序运行时"当前所在的目录"，相对路径基于它解析。

**坑**：`java -jar target/xxx.jar` 在不同目录执行，`students.txt` 会生成在不同位置。

## 八、构建工具（Maven）

### 构建工具（Build Tool）
自动管理"编译 → 测试 → 打包 → 发布"流程的工具。Java 主流是 **Maven** 和 **Gradle**。

### `pom.xml`
**Project Object Model**，Maven 项目的配置文件。声明坐标、依赖、编译版本、打包方式、插件。

### 坐标（Coordinates）
`groupId:artifactId:version` 三要素，唯一标识一个依赖。

```xml
<groupId>org.junit.jupiter</groupId>
<artifactId>junit-jupiter</artifactId>
<version>5.10.2</version>
```

### 依赖（Dependency）
项目需要的外部 jar。Maven 自动从仓库下载，无需手动放置。

### 传递依赖（Transitive Dependency）
A 依赖 B，B 依赖 C，则 A 自动也依赖 C。Maven 自动递归解析。

### scope（作用域）
依赖生效的阶段。

| scope | 作用 |
|---|---|
| `compile`（默认） | 编译、测试、打包都用 |
| `test` | 只在测试时用，不打进最终 jar |
| `provided` | 编译时需要，运行时由容器提供 |

### 本地仓库 / 中央仓库 / 镜像
- **本地仓库**：`~/.m2/repository`，下载的依赖缓存在这
- **中央仓库**：Maven 官方仓库
- **镜像**：中央仓库的加速副本，如阿里云

```xml
<mirror>
    <id>aliyun</id>
    <mirrorOf>central</mirrorOf>
    <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```

### 插件（Plugin）
Maven 的能力扩展。核心只负责调度，具体工作由插件完成。

| 插件 | 作用 |
|---|---|
| `maven-surefire-plugin` | 跑测试 |
| `maven-jar-plugin` | 打 jar |
| `exec-maven-plugin` | `mvn exec:java` 直接运行 |

### 生命周期阶段（Phase）
Maven 的执行流程，按顺序执行：

```
clean → validate → compile → test → package → install → deploy
```

常用命令：

```bash
mvn clean package      # 清空 + 编译 + 测试 + 打包
mvn test               # 编译 + 测试
mvn compile            # 只编译
```

## 九、单元测试

### 单元测试（Unit Test）
用代码测试代码，验证单个方法/类的行为是否正确。

### JUnit 5
Java 最主流的测试框架。

```java
@Test
void findById_shouldReturnStudentWhenExists() {
    StudentManager m = new StudentManager(tempFile);
    m.add(new Student("001", "小明", 85));
    assertNotNull(m.findById("001"));
}
```

### 断言（Assertion）
测试中"检查实际结果是否等于期望结果"。

```java
assertEquals(expected, actual);
assertNotNull(obj);
assertNull(obj);
assertTrue(condition);
```

### AAA 模式
测试的标准结构：

- **Arrange**：准备数据
- **Act**：调用被测方法
- **Assert**：断言结果

### 测试隔离（Test Isolation）
每个测试应独立、不依赖其他测试或真实资源。

```java
@TempDir
Path tempDir;                          // JUnit 自动建临时目录，用完删

new StudentManager(tempDir.resolve("test.txt"));
```

## 十、打包与分发

### jar（Java Archive）
Java 归档文件，本质是 zip。内含 `.class`、`MANIFEST.MF`、资源文件。

```bash
mvn clean package                     # 生成 target/xxx.jar
java -jar target/xxx.jar              # 运行
```

### `MANIFEST.MF`
jar 内的清单文件，可写 `Main-Class` 指定入口类。

```
Main-Class: ui.App
```

### fat jar / uber jar
把项目代码 + 所有依赖打成一个 jar，`java -jar` 即可运行，无需额外 classpath。

### `-jar` 参数
告诉 `java` 命令："参数是 jar 文件，读它的清单找入口"，而非把参数当类名。

```bash
java -jar app.jar       # 运行 jar
java ui.App             # 直接指定类名
```

## 十一、架构与设计

### 分层（Layering）
按职责把代码分成不同层，每层只做一类事。

```
ui      → 输入输出
service → 业务逻辑 + 存储
model   → 数据结构
```

### 耦合（Coupling）
两个模块之间**依赖的紧密程度**。耦合高 = 改一个容易牵连另一个。

| 耦合类型 | 例子 |
|---|---|
| 内容耦合 | 直接改 `public` 字段 |
| 硬编码耦合 | 类里写死 `Paths.get("students.txt")` |
| 跨层耦合 | `ui` 直接调 `Files.write` |
| 时间耦合 | 调用方必须记得手动 `save()` |

### 解耦（Decoupling）
降低模块间依赖，让改动只影响局部。

**手段**：封装、分层、依赖注入、面向接口、方法抽取。

**边界**：解耦要对应真实的"变化点"，过度解耦（为单实现建接口）也是负担。

### 依赖（Dependency）
一个类要用到的其他类/资源。

```java
public class StudentManager {
    private final Path dataFile;         // 依赖 Path
    private final List<Student> students; // 依赖 Student
}
```

### 依赖注入（Dependency Injection, DI）
**依赖不由类自己 `new`，而由外部传入。**

```java
// 改造前：自己写死
private static final Path DATA_FILE = Paths.get("students.txt");

// 改造后：外部传入
public StudentManager(Path dataFile) {
    this.dataFile = dataFile;
}
```

三种形式：

| 形式 | 例子 |
|---|---|
| 构造器注入 | `StudentManager(Path p)` |
| Setter 注入 | `setDataFile(Path p)` |
| 方法参数注入 | `findById(String id)` |

### 控制反转（Inversion of Control, IoC）
**思想**：对象不要自己创建依赖，控制权交给外部。DI 是实现 IoC 的手段之一。

### 面向接口编程（Program to an Interface）
依赖抽象接口而非具体实现，方便替换。

```java
public interface StudentRepository {   // 接口
    List<Student> findAll();
    void save(Student s);
}

public class StudentManager {
    private final StudentRepository repo;   // 依赖接口，不依赖具体实现
}
```

### Repository 模式
把"数据存取"抽象成接口，业务层只依赖接口，底层可以是文件、数据库、缓存。

### 重构（Refactoring）
不改变外部行为的前提下，改进代码内部结构。比如你做的"拆包""抽 `findById`""加 DI"。

### 硬编码（Hardcoding）
把可变的值直接写死在代码里。

```java
Paths.get("students.txt")      // 路径写死，换环境要改代码
```

### 实体类 / DTO
- **Entity（实体类）**：对应数据表/领域对象，如 `Student`
- **DTO（Data Transfer Object）**：用于层间传输数据的对象，字段可能比实体少

## 十二、调试

### 断点（Breakpoint）
代码行上的标记，程序运行到此处暂停。VSCode 里点行号左侧红点。

### 条件断点（Conditional Breakpoint）
满足条件才暂停。右键红点设置，如 `i == 500`。

### 单步执行（Stepping）

| 操作 | 快捷键 | 含义 |
|---|---|---|
| Step Over | `F10` | 执行当前行，不进入方法 |
| Step Into | `F11` | 进入调用的方法内部 |
| Step Out | `Shift+F11` | 从当前方法跳出 |

### 调试控制台（Debug Console）
调试暂停时可输入表达式求值，如 `list.size()`。

### 监视（Watch）
添加表达式，每次单步后自动重新求值。

### `launch.json`
VSCode 调试配置文件，位于 `.vscode/launch.json`。定义入口类、参数、控制台等。

```json
{
    "type": "java",
    "request": "launch",
    "mainClass": "ui.App",
    "args": [],
    "console": "integratedTerminal"
}
```

## 十三、版本控制（Git）

### 仓库（Repository / Repo）
Git 管理的项目目录，含全部历史版本。

### commit
一次提交，记录当前所有改动快照。

```bash
git add .
git commit -m "feat: 添加删除功能"
```

### push / clone
- **push**：本地提交推到远程仓库
- **clone**：把远程仓库完整复制到本地

```bash
git push -u origin main
git clone https://github.com/用户/项目.git
```

### `.gitignore`
声明哪些文件不纳入版本控制。

```
target/
*.class
students.txt
.vscode/
```

### README
项目说明文档，通常包含：简介、功能、技术栈、运行方式、目录结构。

### Personal Access Token（PAT）
GitHub 的访问凭证，替代密码用于 `git push`（GitHub 已不支持密码认证）。

## 十四、前后端与架构角色

### CLI 应用（Command-Line Interface）
命令行程序。通过终端输入输出交互。**你的项目就是 CLI 应用。**

### 前端（Frontend）
用户直接看到和操作的界面层：网页、App 界面。

### 后端（Backend）
通过**网络**为前端提供数据和服务的程序。核心特征：**HTTP 服务、多用户、常驻、数据库**。

| | 后端 | 你的 CLI 程序 |
|---|---|---|
| 调用方式 | 网络（HTTP） | 终端输入 |
| 用户数 | 多用户并发 | 单用户 |
| 运行位置 | 服务器常驻 | 本机一次一跑 |
| 数据存储 | 数据库 | 本地文件 |

**"后端"由角色定义，不由语言定义。** Java 常用于后端，但 Java 代码不等于后端代码。

### REST / HTTP（提到，未深入）
后端接口的常见风格。用 HTTP 方法表示操作：

| 方法 | 操作 | 例子 |
|---|---|---|
| GET | 查询 | `GET /students` |
| POST | 新增 | `POST /students` |
| PUT | 修改 | `PUT /students/001` |
| DELETE | 删除 | `DELETE /students/001` |

### JDBC（Java Database Connectivity）
Java 操作数据库的标准 API。

```java
Connection conn = DriverManager.getConnection("jdbc:sqlite:students.db");
PreparedStatement ps = conn.prepareStatement("SELECT * FROM student");
ResultSet rs = ps.executeQuery();
```

### 并发 / 竞态条件 / synchronized（提到，未深入）
- **并发（Concurrency）**：多个线程同时执行
- **竞态条件（Race Condition）**：多线程访问共享数据导致结果不可预测
- **`synchronized`**：加锁，保证同一时刻只有一个线程执行
