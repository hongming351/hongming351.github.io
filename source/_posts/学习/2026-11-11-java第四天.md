# Spring Boot 改造复盘：控制台程序 → REST 后端

> 核心成果：同一套业务逻辑（`StudentManager`），从"终端交互"变成"HTTP 服务"。
> 改造过程中 `StudentManager` 几乎没改——这是前面分层和依赖注入的回报。

## 三、核心注解速查

| 注解 | 作用 | 用在哪 |
|---|---|---|
| `@SpringBootApplication` | 启动类，组合了三个注解 | `main` 方法所在类 |
| `@RestController` | 类内方法返回值直接作为 JSON 响应 | Controller 类 |
| `@RequestMapping("/students")` | 类级路径前缀 | Controller 类 |
| `@GetMapping` / `@PostMapping` / `@PutMapping` / `@DeleteMapping` | 对应 HTTP 方法 | 方法 |
| `@PathVariable` | 从 URL 路径取参数，如 `/students/001` | 方法参数 |
| `@RequestParam` | 从查询字符串取参数，如 `?name=小` | 方法参数 |
| `@RequestBody` | 请求体 JSON 反序列化成对象 | 方法参数 |
| `@Service` | 业务层组件，交给 Spring 管理 | Service 类 |
| `@Repository` | 存储层组件 | Repository 实现 |
| `@Primary` | 多个候选 bean 时优先用这个 | Repository 实现 |
| `@JsonCreator` / `@JsonProperty` | 让 Jackson 通过构造器反序列化 | 实体类构造器 |
| `ResponseEntity` | 控制状态码 + 响应体 | 方法返回值 |

## 四、搬 model：加 JSON 反序列化支持

### 4.1 改造后的 `Student`

```java
package com.demo.studentmanager.model;

import com.fasterxml.jackson.annotation.JsonCreator;
import com.fasterxml.jackson.annotation.JsonProperty;

public class Student {
    private final String id;
    private String name;
    private double score;

    @JsonCreator
    public Student(@JsonProperty("id") String id,
                   @JsonProperty("name") String name,
                   @JsonProperty("score") double score) {
        this.id = id;
        this.name = name;
        this.score = score;
    }

    public String getId() { return id; }
    public String getName() { return name; }
    public double getScore() { return score; }
    public void setName(String name) { this.name = name; }
    public void setScore(double score) { this.score = score; }
}
```

### 4.2 和旧版本的区别

| 变化 | 原因 |
|---|---|
| 删掉 `toCsv()` | CSV 是文件存储的事，用数据库后不需要 |
| 加 `@JsonCreator` + `@JsonProperty` | 让 Jackson 能把 JSON 反序列化成 `Student` |

**没有这两个注解会怎样**：`POST /students` 收到 JSON 时，Jackson 不知道怎么创建对象，会报 `HttpMessageNotReadableException`。

**为什么 `id` 是 `final` 且没有 `setId`**：学号是唯一标识，不允许改。这是封装的设计决策。

## 五、搬 repository：加 `@Repository` 和 `@Primary`

### 5.1 接口不变

```java
package com.demo.studentmanager.repository;

import com.demo.studentmanager.model.Student;
import java.util.List;

public interface StudentRepository {
    List<Student> findAll();
    Student findById(String id);
    void save(Student student);
    boolean delete(String id);
    int count();
    List<Student> findByNameLike(String keyword);
}
```

### 5.2 SQLite 实现加 `@Repository` 和 `@Primary`

```java
package com.demo.studentmanager.repository;

import org.springframework.context.annotation.Primary;
import org.springframework.stereotype.Repository;

@Repository
@Primary                                 // 有多个实现时优先用这个
public class SqliteStudentRepository implements StudentRepository {
    // 逻辑和旧项目一样，只改 package 和 import
}
```

### 5.3 内存实现加 `@Repository`

```java
@Repository
public class InMemoryStudentRepository implements StudentRepository {
    // 逻辑不变
}
```

### 5.4 两个注解的含义

| 注解 | 作用 |
|---|---|
| `@Repository` | 告诉 Spring 这是存储层组件，创建实例放进容器 |
| `@Primary` | **有多个同类型 bean 时，优先注入标了 `@Primary` 的** |

**没有 `@Primary` 会怎样**：

```
NoUniqueBeanDefinitionException:
expected single matching bean but found 2:
sqliteStudentRepository, inMemoryStudentRepository
```

Spring 发现两个 `StudentRepository` 实现，不知道注入哪个，启动失败。加 `@Primary` 解决。

## 六、搬 service：加 `@Service`

### 6.1 改造后的 `StudentManager`

```java
package com.demo.studentmanager.service;

import com.demo.studentmanager.model.Student;
import com.demo.studentmanager.repository.StudentRepository;
import org.springframework.stereotype.Service;

import java.util.ArrayList;
import java.util.List;

@Service
public class StudentManager {
    private final StudentRepository repo;

    public StudentManager(StudentRepository repo) {
        this.repo = repo;
    }

    public void add(Student s) { repo.save(s); }
    public void save(Student s) { repo.save(s); }
    public List<Student> getAll() { return repo.findAll(); }
    public boolean isEmpty() { return repo.count() == 0; }
    public int size() { return repo.count(); }
    public Student findById(String id) { return repo.findById(id); }
    public boolean delete(Student s) { return repo.delete(s.getId()); }
    public List<Student> findByNameLike(String keyword) { return repo.findByNameLike(keyword); }

    public List<Student> getAllSortedByScore() {
        List<Student> copy = new ArrayList<>(repo.findAll());
        copy.sort((a, b) -> Double.compare(b.getScore(), a.getScore()));
        return copy;
    }
}
```

### 6.2 关键：构造器注入不用 `@Autowired`

```java
public StudentManager(StudentRepository repo) {
    this.repo = repo;
}
```

**Spring 4.3 之后，类只有一个构造器时，Spring 自动用它注入**，不需要 `@Autowired`。这就是旧项目里手写的构造器注入，Spring 帮你做了。

### 6.3 旧项目 vs 新项目对比

| | 旧项目（控制台） | 新项目（Spring Boot） |
|---|---|---|
| 类注解 | 无 | `@Service` |
| 依赖注入 | 手写 `new StudentManager(new SqliteStudentRepository(...))` | Spring 自动注入 |
| 业务逻辑 | 一样 | **一行没改** |

**这是最值得体会的一点**：`StudentManager` 的逻辑完全没变，只加了 `@Service`，就从"手动装配"变成"自动装配"。

## 七、写 Controller：7 个 REST 接口

### 7.1 完整代码

```java
package com.demo.studentmanager.controller;

import com.demo.studentmanager.model.Student;
import com.demo.studentmanager.service.StudentManager;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.util.List;
import java.util.Map;

@RestController
@RequestMapping("/students")
public class StudentController {
    private final StudentManager manager;

    public StudentController(StudentManager manager) {
        this.manager = manager;
    }

    // 查询全部，可选按成绩排序
    @GetMapping
    public List<Student> getAll(@RequestParam(required = false) String sort) {
        if ("score".equals(sort)) {
            return manager.getAllSortedByScore();
        }
        return manager.getAll();
    }

    // 按学号查
    @GetMapping("/{id}")
    public ResponseEntity<Student> getById(@PathVariable String id) {
        Student s = manager.findById(id);
        return s == null ? ResponseEntity.notFound().build() : ResponseEntity.ok(s);
    }

    // 姓名模糊搜索
    @GetMapping("/search")
    public List<Student> search(@RequestParam String name) {
        return manager.findByNameLike(name);
    }

    // 统计
    @GetMapping("/stats")
    public Map<String, Object> stats() {
        List<Student> all = manager.getAll();
        if (all.isEmpty()) {
            return Map.of("count", 0);
        }
        double sum = 0;
        Student top = all.get(0);
        for (Student s : all) {
            sum += s.getScore();
            if (s.getScore() > top.getScore()) top = s;
        }
        return Map.of("count", all.size(), "average", sum / all.size(), "top", top);
    }

    // 新增
    @PostMapping
    public ResponseEntity<Student> add(@RequestBody Student student) {
        manager.add(student);
        return ResponseEntity.ok(student);
    }

    // 修改
    @PutMapping("/{id}")
    public ResponseEntity<Student> update(@PathVariable String id, @RequestBody Student body) {
        Student existing = manager.findById(id);
        if (existing == null) {
            return ResponseEntity.notFound().build();
        }
        existing.setName(body.getName());
        existing.setScore(body.getScore());
        manager.save(existing);
        return ResponseEntity.ok(existing);
    }

    // 删除
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> delete(@PathVariable String id) {
        Student s = manager.findById(id);
        if (s == null) {
            return ResponseEntity.notFound().build();
        }
        manager.delete(s);
        return ResponseEntity.noContent().build();
    }
}
```

### 7.2 接口一览

| 方法 | 路径 | 说明 | 状态码 |
|---|---|---|---|
| GET | `/students` | 查询全部 | 200 |
| GET | `/students?sort=score` | 按成绩降序 | 200 |
| GET | `/students/{id}` | 按学号查 | 200 / 404 |
| GET | `/students/search?name=小` | 模糊搜索 | 200 |
| GET | `/students/stats` | 统计 | 200 |
| POST | `/students` | 新增 | 200 |
| PUT | `/students/{id}` | 修改 | 200 / 404 |
| DELETE | `/students/{id}` | 删除 | 204 / 404 |

### 7.3 `ResponseEntity` 的用法

```java
// 404
return ResponseEntity.notFound().build();

// 200 + 对象
return ResponseEntity.ok(student);

// 204（无内容）
return ResponseEntity.noContent().build();

// 400 + 错误信息
return ResponseEntity.badRequest().body(Map.of("error", "参数错误"));
```

**为什么用 `ResponseEntity` 而不是直接返回对象**：直接返回对象永远是 `200`，无法表达"没找到"（404）、"删除成功"（204）等语义。REST 的规范之一是**状态码要准确**。

### 7.4 路由顺序的坑

`/students/{id}` 和 `/students/search` 看起来冲突，但**Spring 优先精确匹配**：

- `/students/search` → 走 `search()` 方法
- `/students/001` → 走 `getById()` 方法

只要 `search` 和 `stats` 这类精确路径的方法先定义，就不会被 `{id}` 截胡。

## 十、常见坑清单

| 现象 | 原因 | 解决 |
|---|---|---|
| `NoUniqueBeanDefinitionException` | 两个 `StudentRepository` 实现，Spring 不知道注入哪个 | 给 SQLite 实现加 `@Primary` |
| `HttpMessageNotReadableException` | `Student` 没有 `@JsonCreator`，Jackson 无法反序列化 | 加 `@JsonCreator` + `@JsonProperty` |
| `404` 访问 `/students` | 忘了 `@RequestMapping("/students")` 或方法上没 `@GetMapping` | 检查注解 |
| 返回的不是 JSON | 用了 `@Controller` 而不是 `@RestController` | 改成 `@RestController` |
| `curl` 在 PowerShell 行为异常 | `curl` 是 `Invoke-WebRequest` 的别名 | 用 `curl.exe` 或 Postman |
| `students.db` 位置不对 | 相对路径基于工作目录 | 打印绝对路径确认 |
| `ClassNotFoundException: org.sqlite.JDBC` | `pom.xml` 缺 SQLite 依赖 | start.spring.io 选 SQLite Driver，或手动加 `sqlite-jdbc` |

## 十一、核心收获

### 11.1 分层和依赖注入的回报

旧项目里手写的：

```java
new StudentManager(new SqliteStudentRepository("students.db"))
```

新项目里变成：

```java
@Repository @Primary class SqliteStudentRepository implements StudentRepository { ... }
@Service class StudentManager { public StudentManager(StudentRepository repo) { ... } }
```

**Spring 自动完成了"构造并注入"**。如果前面没有把依赖抽成接口，Spring 也帮不了你——**能自动注入的前提是"依赖的是接口"**。

### 11.2 什么是"真正的后端"

| | 你的 REST 版 |
|---|---|
| HTTP 服务 | ✅ Tomcat 监听 8080 |
| 接收网络请求 | ✅ `@GetMapping` / `@PostMapping` |
| 返回 JSON | ✅ Jackson 自动序列化 |
| 多客户端访问 | ✅ 任何能发 HTTP 的客户端 |
| 数据持久化 | ✅ SQLite |

**这就是后端**——不再是"本机终端跑一次"，而是"持续监听，等请求进来"。

### 11.3 面试话术

> "我把控制台版改造成了 Spring Boot REST 后端，核心业务逻辑 `StudentManager` 几乎没改，只加了 `@Service` 注解。因为前面已经做了 Repository 接口抽象和构造器注入，Spring 的自动装配直接适用。接口是 REST 风格，用 `@RestController` 暴露 7 个端点，`@RequestBody` 接收 JSON，`ResponseEntity` 控制状态码，数据持久化到 SQLite。"

**这段话里的每个技术点都有代码对应，不是背的。**
