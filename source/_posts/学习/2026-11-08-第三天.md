## 一、SQLite 基础

### 1.1 是什么

一个**无需安装服务器**的数据库，整个数据库就是**一个文件**（如 `students.db`）。

| | MySQL | SQLite |
|---|---|---|
| 安装 | 需要装服务、配账号密码 | 加一个 jar 依赖即可 |
| 进程 | 独立服务进程，通过网络连接 | 无进程，程序直接读写文件 |
| 适用 | 生产环境、多用户并发 | 学习、桌面应用、小型项目 |
| 备份 | 导出 SQL | 复制文件 |

**为什么入门选 SQLite**：零配置，不会卡在"装 MySQL 失败"上，注意力集中在 SQL 和 JDBC 本身。

### 1.2 数据库文件位置

```java
"jdbc:sqlite:students.db"          // 相对当前工作目录
"jdbc:sqlite:/abs/path/students.db" // 绝对路径
"jdbc:sqlite::memory:"              // 内存数据库，进程结束即消失
```

**坑**：相对路径相对于**执行命令的目录**，不是 jar 所在目录。

## 二、JDBC 核心

### 2.1 是什么

**Java Database Connectivity**，Java 操作数据库的**标准 API**。不管底层是 MySQL、SQLite 还是 Oracle，代码结构完全一样，只换 URL 和驱动 jar。

### 2.2 四步流程

```java
// 1. 连接
try (Connection conn = DriverManager.getConnection(url)) {

    // 2. 准备 SQL（用 ? 占位）
    String sql = "INSERT INTO student (id, name, score) VALUES (?, ?, ?)";
    try (PreparedStatement ps = conn.prepareStatement(sql)) {

        // 3. 填参数 + 执行
        ps.setString(1, "001");
        ps.setString(2, "小明");
        ps.setDouble(3, 85.5);
        ps.executeUpdate();

    } // 4. 自动关闭 PreparedStatement
} // 自动关闭 Connection
```

### 2.3 核心 API

| 接口/类 | 作用 |
|---|---|
| `DriverManager` | 根据 URL 获取 `Connection` |
| `Connection` | 一个数据库连接 |
| `PreparedStatement` | 预编译 SQL，支持 `?` 占位符 |
| `Statement` | 直接执行静态 SQL（不推荐） |
| `ResultSet` | 查询结果集，用 `next()` 遍历 |
| `SQLException` | JDBC 所有异常的父类（**受检异常**） |

### 2.4 `executeUpdate` vs `executeQuery`

| 方法 | 用于 | 返回值 |
|---|---|---|
| `executeUpdate()` | INSERT / UPDATE / DELETE / CREATE | `int`，影响行数 |
| `executeQuery()` | SELECT | `ResultSet` |
| `execute()` | 通用（少见） | `boolean`，有结果集返回 true |

**判断操作成功**：看 `executeUpdate()` 返回的行数。`0` 表示没匹配到记录。

### 2.5 `ResultSet` 遍历

```java
try (ResultSet rs = ps.executeQuery()) {
    while (rs.next()) {                          // 游标下移一行，有数据返回 true
        String id = rs.getString("id");          // 按列名读
        double score = rs.getDouble("score");    // 按类型读
    }
}
```

`rs.next()` 初始时游标在第一行**之前**，必须先调一次 `next()` 才能读第一行。

## 三、SQL 五件套

### 3.1 建表

```sql
CREATE TABLE IF NOT EXISTS student (
    id    TEXT PRIMARY KEY,
    name  TEXT NOT NULL,
    score REAL NOT NULL
);
```

- `PRIMARY KEY`：主键，唯一且非空，重复插入会报 `UNIQUE constraint failed`
- `NOT NULL`：非空约束
- `IF NOT EXISTS`：表已存在时不报错，可重复执行

### 3.2 增 / 查 / 改 / 删

```sql
-- 增
INSERT INTO student (id, name, score) VALUES (?, ?, ?);

-- 查
SELECT id, name, score FROM student;
SELECT id, name, score FROM student WHERE id = ?;

-- 改
UPDATE student SET name = ?, score = ? WHERE id = ?;

-- 删
DELETE FROM student WHERE id = ?;
```

### 3.3 类型映射

| Java | SQL |
|---|---|
| `String` | `TEXT` |
| `int` / `Integer` | `INTEGER` |
| `double` / `Double` | `REAL` |
| `boolean` | `INTEGER`（0/1） |

### 3.4 upsert：`INSERT OR REPLACE`

```sql
INSERT OR REPLACE INTO student (id, name, score) VALUES (?, ?, ?);
```

**语义**：主键不存在则插入，存在则**替换整行**。

这就是为什么 `Repository` 接口只有一个 `save` 方法，不用区分 `insert` 和 `update`——数据库层天然支持 upsert。

## 四、PreparedStatement vs Statement

### 4.1 为什么用 PreparedStatement

| | Statement | PreparedStatement |
|---|---|---|
| 占位符 | 无，字符串拼接 | 支持 `?` |
| SQL 注入 | **有风险** | 安全 |
| 预编译 | 否 | 是，重复执行更快 |
| 类型安全 | 无 | `setXxx` 指定类型 |

### 4.2 反例：字符串拼接（危险）

```java
String sql = "SELECT * FROM student WHERE id = '" + id + "'";
// 如果 id 是 "' OR '1'='1"，会查出所有数据
```

### 4.3 正例：占位符

```java
String sql = "SELECT * FROM student WHERE id = ?";
ps.setString(1, id);      // id 被当成纯值，不是 SQL 片段
```

### 4.4 setXxx 下标从 1 开始

```java
ps.setString(1, "001");   // 第 1 个 ?
ps.setString(2, "小明");  // 第 2 个 ?
ps.setDouble(3, 85.5);    // 第 3 个 ?
```

**这是 JDBC 最容易记错的地方**：SQL 里的 `?` 从 1 开始编号，不是 0。

## 五、异常处理策略

### 5.1 SQLException 是受检异常

`SQLException` 继承自 `Exception`，**必须处理**（`try-catch` 或 `throws`）。这意味着如果接口方法声明了它，所有调用方都要跟着处理，非常啰嗦。

### 5.2 策略：接口不抛，实现包装

**接口保持干净**：

```java
public interface StudentRepository {
    List<Student> findAll();          // 不 throws
    Student findById(String id);
    void save(Student student);
    boolean delete(String id);
}
```

**实现里把受检异常转成运行时异常**：

```java
@Override
public List<Student> findAll() {
    try (...) {
        // ...
    } catch (SQLException e) {
        throw new RuntimeException("查询失败", e);   // 保留原始异常作为 cause
    }
}
```

**好处**：

- 业务层和 UI 层不用到处写 `try-catch`
- 原始 `SQLException` 作为 `cause` 保留，堆栈信息不丢
- 出错时是"数据库操作失败"，属于真正的运行时故障，不是调用方该处理的

**真实项目**：会定义一个 `DataAccessException` 继承 `RuntimeException`，统一处理。现在是学习阶段，用 `RuntimeException` 足够。

## 六、Repository 模式

### 6.1 是什么

把**数据存取**抽象成接口，业务层只依赖接口，底层可以是文件、数据库、缓存、远程服务。

### 6.2 接口定义

```java
public interface StudentRepository {
    List<Student> findAll();
    Student findById(String id);
    void save(Student student);
    boolean delete(String id);
    int count();
}
```

**接口设计的原则**：

- 只暴露业务需要的能力，不暴露 SQL 细节
- 方法名是业务语言（`findById`），不是数据库语言（`selectById`）
- `save` 用 upsert 语义，不区分 `insert` / `update`

### 6.3 两个实现对比

| | `SqliteStudentRepository` | `InMemoryStudentRepository` |
|---|---|---|
| 底层 | SQLite 数据库 | `LinkedHashMap` |
| 持久化 | 是，进程结束还在 | 否，进程结束就没了 |
| 速度 | 有 IO 开销 | 极快 |
| 用途 | 生产运行 | 单元测试 |

**两个实现代码几乎不重叠**，但都能被 `StudentManager` 使用，因为它们**实现同一个接口**。

### 6.4 依赖方向

```
ui.App  →  service.StudentManager  →  repository.StudentRepository（接口）
                                            ↑
                              ┌─────────────┴─────────────┐
                    SqliteStudentRepository      InMemoryStudentRepository
```

**关键**：`StudentManager` 只认识接口，**不认识任何实现类**。这就是"依赖倒置"。

## 七、依赖注入进阶：从注入 Path 到注入接口

### 7.1 三个阶段

| 阶段 | 依赖类型 | 问题 |
|---|---|---|
| 改造前 | 类内部写死 `Paths.get("students.txt")` | 测试会覆盖真实数据 |
| 第 6 步 | 注入 `Path dataFile` | 能测试了，但只能在"文件"里换 |
| 现在 | 注入 `StudentRepository` | 能换**存储方式**（文件/数据库/内存） |

### 7.2 构造器注入

```java
public class StudentManager {
    private final StudentRepository repo;

    public StudentManager(StudentRepository repo) {
        this.repo = repo;
    }
}
```

**`final` 的意义**：依赖一旦注入就不能换，保证对象状态稳定。

### 7.3 装配点在 main

```java
static StudentManager manager = new StudentManager(
        new SqliteStudentRepository("students.db"));
```

**`main` 方法就是"容器"**，负责把依赖组装好。Spring 框架做的就是这件事，只是从手工 `new` 变成自动扫描。

## 八、可测试性

### 8.1 测试不再依赖外部资源

```java
class StudentManagerTest {
    private StudentManager newManager() {
        return new StudentManager(new InMemoryStudentRepository());
    }

    @Test
    void findById_shouldReturnStudentWhenExists() {
        StudentManager m = newManager();
        m.add(new Student("001", "小明", 85));
        assertNotNull(m.findById("001"));
    }
}
```

**对比改造前**：以前要 `@TempDir` 建临时文件，现在一个 `new` 搞定。**零 IO、无文件、跑得飞快、互不干扰**。

### 8.2 这就是"依赖注入 + 面向接口"的实战价值

面试回答"为什么要用依赖注入"，标准答案不是"解耦"这种空话，而是：

> "我写 `StudentManager` 的单元测试时，用 `InMemoryStudentRepository` 替换 `SqliteStudentRepository`，测试完全不碰数据库，跑一次不到 1 秒。这是依赖注入带来的可测试性。"

## 九、文件存储 vs 数据库存储：完整对比

| 维度 | 文件（`students.txt`） | 数据库（`students.db`） |
|---|---|---|
| 数据格式 | 自己定 CSV | 表结构，强类型 |
| 查询 | 全部读入内存再遍历 | `WHERE` 条件过滤，可建索引 |
| 并发 | 无保护，会互相覆盖 | 有事务和锁机制 |
| 部分更新 | 整个文件重写 | `UPDATE` 只改一行 |
| 数据量 | 几千行以下 | 百万级以上 |
| 防注入 | 需自己处理逗号、换行 | `PreparedStatement` 天然防 |
| 事务 | 无 | `BEGIN / COMMIT / ROLLBACK` |

**文件版适合**：配置、日志、小数据量、快速原型。
**数据库版适合**：业务数据、需要查询和更新、多用户、大数据量。

## 十、常见坑清单

| 现象 | 原因 | 解决 |
|---|---|---|
| `No suitable driver found for jdbc:sqlite` | 依赖没加或没同步 | `pom.xml` 检查 `sqlite-jdbc`，`mvn clean compile` |
| `ClassNotFoundException: org.sqlite.JDBC` | jar 没进 classpath | 同上 |
| `UNIQUE constraint failed` | 用了 `INSERT` 而不是 `INSERT OR REPLACE` | 改 upsert |
| `database is locked` | 另一个连接没关，或 SQLite Viewer 开着文件 | 关掉工具重试 |
| 测试时数据消失/被覆盖 | 测试用了真实 `SqliteStudentRepository` | 测试改用 `InMemoryStudentRepository` |
| 找不到 `students.db` | 相对路径基于工作目录 | 用绝对路径打印确认 `new File("students.db").getAbsolutePath()` |
| `rs.getString(0)` 报错 | `ResultSet` 下标从 1 开始 | 改成 `rs.getString(1)` |
| `ps.setString(0, ...)` 报错 | `PreparedStatement` 下标也从 1 开始 | 改成 `ps.setString(1, ...)` |

## 十二、面试话术（把这两天的成果讲出来）

> "我做了一个学生管理系统，存储层用 Repository 接口做了抽象，业务层 `StudentManager` 只依赖接口，不依赖具体存储。
>
> 目前有两个实现：`SqliteStudentRepository` 用 JDBC + SQLite，`InMemoryStudentRepository` 用 HashMap。生产运行用前者，单元测试用后者，做到零 IO、无外部依赖。
>
> 如果要换成 MySQL，只需要新增一个 `MysqlStudentRepository implements StudentRepository`，`StudentManager` 和 UI 层一行不用改。
>
> 技术栈：Java 21、Maven、JUnit 5、JDBC、SQLite。"

**这段话覆盖了**：面向接口、依赖注入、可测试性、存储可替换、JDBC 实操。比"我会用 SQL"有分量得多。

## 十四、下一步可选方向

| 方向 | 内容 | 练什么 |
|---|---|---|
| A-3 | 加 `MysqlStudentRepository` | JDBC 通用性、连接池、驱动差异 |
| A-3 | 给 SQLite 加事务（批量插入） | `setAutoCommit(false)`、`commit`/`rollback` |
| B | Spring Boot 改造 | `@Service`、`@Repository`、自动注入 |
| C | 并发（多线程同时操作） | `synchronized`、竞态条件 |
| D | 加功能（按姓名模糊搜索、分页） | `LIKE`、`LIMIT OFFSET` |

**建议下一步走 B（Spring Boot）**：你现在的项目结构和 Spring 的思想完全对得上，转过去会非常顺——把 `StudentManager` 标 `@Service`、`SqliteStudentRepository` 标 `@Repository`、构造器注入换成 `@Autowired`（甚至不用标，Spring 自动注入构造器参数），就是 Spring 项目了。
