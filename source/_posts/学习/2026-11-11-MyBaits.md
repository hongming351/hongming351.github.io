# MyBatis 核心概念总结

MyBatis 是一款优秀的半自动 ORM（对象关系映射）框架，它巧妙地将 SQL 的控制权交还给开发者，同时封装了繁琐的 JDBC 操作，在灵活性与开发效率之间取得了很好的平衡。它的核心概念可以围绕**架构分层、核心对象、工作流程与关键特性**四个方面来理解。

---

## 🏗️ 三层功能架构

MyBatis 的功能架构清晰，主要分为三层，各司其职：

- **API 接口层**：这是开发者与 MyBatis 交互的"门面"。其核心是 `SqlSession` 接口，它提供了操作数据库的所有方法（增删改查、事务提交等）。开发者通过这一层发起请求，无需关心底层细节。
- **数据处理层**：这是 MyBatis 的核心引擎。它负责完成一次数据库操作的全部实质工作，包括：SQL 解析、参数映射（Java 类型与 JDBC 类型转换）、SQL 执行以及结果集映射（将数据库结果转换为 Java 对象）。
- **基础支撑层**：这是框架的"地基"，提供通用基础服务。包括连接管理、事务管理、配置加载、缓存处理、反射模块、日志模块等，为上层的功能提供稳定支撑。

---

## 🧩 核心对象（组件）及其职责

MyBatis 的运行依赖于一系列分工明确的核心对象，它们协同完成一次数据库访问。

| 核心对象 | 核心职责 | 关键说明 |
|---|---|---|
| `SqlSessionFactory` | 工厂，用于创建 `SqlSession` | 它是应用级单例，生命周期与整个应用共存亡，通过 `SqlSessionFactoryBuilder` 解析配置构建。 |
| `SqlSession` | 会话，代表与数据库的一次交互 | 它是非线程安全的，生命周期短，每次数据库操作都应创建新的实例，用完即关。它封装了所有执行 SQL 的方法。 |
| `Executor` | 执行器，是调度的核心 | 负责生成 SQL 语句、维护查询缓存，并调度 `StatementHandler` 等组件完成实际执行。MyBatis 提供了 `SimpleExecutor`、`ReuseExecutor`、`BatchExecutor` 等多种实现。 |
| `MappedStatement` | SQL 的完整描述 | 它封装了一条 SQL 语句的全部信息，如 statementId（唯一标识）、SQL 语句、参数映射、结果映射、缓存配置等。每条 `<select>`/`<insert>` 标签都会解析为一个该对象。 |
| `Configuration` | 全局配置容器 | 持有 MyBatis 的所有配置信息（数据源、Mapper 映射、类型处理器、缓存开关等），是创建其他核心对象的工厂。它在初始化后不可变，以保证线程安全。 |

此外，**Mapper 接口**是更推荐的交互方式。MyBatis 会通过动态代理为接口自动生成实现类，最终仍是通过 `SqlSession` 来执行数据库操作。

---

## 🔄 核心工作流程

一次典型的 MyBatis 查询请求，其流程可以抽象为以下步骤：

1. **加载配置**：应用启动时，解析 `mybatis-config.xml` 和 Mapper 文件，构建出全局唯一的 `Configuration` 对象和 `SqlSessionFactory`。
2. **获取会话**：通过 `SqlSessionFactory` 打开一个 `SqlSession`。
3. **获取代理**：通过 `SqlSession` 获取 Mapper 接口的代理对象。
4. **发起调用**：调用 Mapper 接口方法。代理对象会根据接口全限定名 + 方法名找到对应的 `MappedStatement`（即 statementId）。
5. **执行器调度**：`SqlSession` 将请求委托给 `Executor`。`Executor` 首先检查缓存，若未命中，则准备 SQL 并调度 `StatementHandler` 执行。
6. **执行与映射**：`StatementHandler` 通过 JDBC 执行 SQL，`ResultSetHandler` 将数据库结果集映射为 Java 对象返回。
7. **关闭会话**：操作完成，提交事务（如需），并关闭 `SqlSession`。

## ⚙️ 关键特性与机制

### 动态 SQL

这是 MyBatis 最强大的特性之一，允许在 XML 映射文件中根据条件动态拼接 SQL 语句，避免了在 Java 代码中手动拼串的麻烦和风险。核心标签包括：

- `<if>`：条件判断，满足时拼接 SQL 片段。
- `<choose>`/`<when>`/`<otherwise>`：类似 Java 的 switch，从多个条件中选择一个。
- `<where>`：智能处理 WHERE 子句，会自动去除开头多余的 AND 或 OR。
- `<set>`：智能处理 SET 子句，自动去除末尾多余的逗号。
- `<foreach>`：用于遍历集合，常用于构建 IN 条件。
- `<trim>`：更通用的标签，可自定义去除或添加前缀/后缀。

### 两级缓存机制

MyBatis 内置了缓存机制以减少数据库查询次数，提升性能。

| 缓存级别 | 作用域 | 默认状态 | 特点与说明 |
|---|---|---|---|
| 一级缓存 | `SqlSession` 级别 | 默认开启，不可关闭 | 同一个 `SqlSession` 内，相同的查询会直接命中缓存。当执行增删改操作或关闭 SqlSession 时，缓存会被清空。 |
| 二级缓存 | Mapper (namespace) 级别 | 需要手动配置开启 | 可以跨多个 `SqlSession` 共享，作用域是同一个 Mapper 命名空间。需要配置 `<cache/>` 标签，且实体类通常需要实现 `Serializable` 接口。注意：因其易产生脏数据且分布式环境下管理复杂，实际项目中常被 Redis 等外部缓存替代。 |

### 其他重要概念

- **插件（Plugin）**：MyBatis 提供了强大的拦截器机制，允许你拦截 `Executor`、`StatementHandler` 等核心对象的执行，实现分页、SQL 监控、性能分析等功能。
- **延迟加载（懒加载）**：在关联查询（如一对多、多对一）中，可以实现"按需加载"，即真正访问关联对象的数据时，才去执行对应的 SQL 查询，有助于减少不必要的数据库交互。
- **TypeHandler（类型处理器）**：负责在 Java 类型（如 String）和 JDBC 类型（如 VARCHAR）之间进行转换。MyBatis 内置了丰富的处理器，也支持自定义。

> MyBatis 的核心可以概括为：以 `Configuration` 为配置中心，由 `SqlSessionFactory` 生产 `SqlSession`，通过 `Executor` 调度，将 `MappedStatement` 中定义的 SQL（可含动态 SQL）执行，并借助缓存和插件等机制，完成高效、灵活的数据持久化操作。

# 知识点代码示例详解

以下为每个核心知识点，逐一附上可运行的代码示例与逐行讲解，方便对照理解。

## 🏗️ 核心对象：SqlSessionFactory → SqlSession

MyBatis 的启动本质是三步：读取配置 → 建造工厂 → 打开会话。`SqlSessionFactoryBuilder` 是一次性工具，`SqlSessionFactory` 是应用级单例，`SqlSession` 是短生命周期的数据库会话（非线程安全，用完即关）。

```java
// 1. 读取核心配置文件（放在 classpath 下）
InputStream is = Resources.getResourceAsStream("mybatis-config.xml");

// 2. Builder 建造 SqlSessionFactory（建造者模式，Builder 用完即弃）
SqlSessionFactoryBuilder builder = new SqlSessionFactoryBuilder();
SqlSessionFactory factory = builder.build(is);

// 3. 工厂打开 SqlSession（工厂模式，Factory 全局单例）
// openSession(true) 表示自动提交事务；默认 false 需手动 commit
try (SqlSession session = factory.openSession(true)) {

    // 4a. 方式一：直接调用 SqlSession 的方法（需要 statementId）
    List<User> users = session.selectList(
        "com.example.mapper.UserMapper.findAll"
    );
    users.forEach(System.out::println);

    // 4b. 方式二（推荐）：获取 Mapper 代理对象
    // 详见下一节的动态代理示例
}
// try-with-resources 自动 close()，SqlSession 实现了 AutoCloseable
```

`session.selectList` 中的 statementId 必须与 Mapper XML 中 `<select>` 的 id 完全匹配（通常写成 `命名空间 + 方法名`）。`SqlSession` 实现了 `AutoCloseable`，推荐使用 try-with-resources 确保关闭，否则连接可能泄漏。

## 🧩 Mapper 接口动态代理

传统 Dao 模式需要手写实现类，而 Mapper 动态代理只需声明接口，MyBatis 通过 JDK 动态代理在运行时生成实现，将接口方法映射到 XML 中的 SQL。这是现代 MyBatis 开发的主流方式。

**① 声明接口**（可加 `@Mapper`，也可用 `@MapperScan` 统一扫描）

```java
@Mapper
public interface UserMapper {

    // 方法名 = XML 中 statement 的 id
    // 参数类型 = parameterType
    // 返回值类型 = resultType
    User getUserById(int id);
}
```

**② XML 映射**（namespace 必须是接口的全限定名）

```xml
<mapper namespace="com.example.mapper.UserMapper">

    <select id="getUserById" parameterType="int"
            resultType="com.example.entity.User">
        SELECT * FROM users WHERE id = #{id}
    </select>

</mapper>
```

**③ 使用代理对象**（无需实现类）

```java
try (SqlSession session = sqlSessionFactory.openSession()) {
    // getMapper 返回 MyBatis 生成的 JDK 动态代理对象
    UserMapper mapper = session.getMapper(UserMapper.class);

    User user = mapper.getUserById(1);
    System.out.println(user);
}
```

`session.getMapper(UserMapper.class)` 实际返回的是 `MapperProxy` 代理对象。代理对象在调用方法时，会根据 **"接口全限定名 + 方法名"** 找到 `MappedStatement`，然后委托 `SqlSession` 执行 SQL。接口方法不能重载，否则 statementId 无法唯一对应。

## ⚙️ 动态 SQL

动态 SQL 允许在 XML 中根据参数条件拼接 SQL，避免 Java 代码里手动拼串。以下是最常用的四个标签的完整示例。

**① `<if>`：条件拼接**

```xml
<select id="findUserByCondition" parameterType="map" resultType="User">
    SELECT * FROM users
    <where>
        <if test="name != null and name != ''">
            AND name = #{name}
        </if>
        <if test="age != null">
            AND age = #{age}
        </if>
    </where>
</select>
```

`<where>` 会智能处理：如果内部有内容，自动加上 `WHERE`；如果第一个有效条件是 `AND`/`OR`，会自动去掉。

**② `<choose>`/`<when>`/`<otherwise>`：多选一（类似 switch）**

```xml
<select id="findUserByCondition" parameterType="map" resultType="User">
    SELECT * FROM users
    <where>
        <choose>
            <when test="name != null">
                AND name = #{name}
            </when>
            <when test="age != null">
                AND age = #{age}
            </when>
            <otherwise>
                AND status = 'active'
            </otherwise>
        </choose>
    </where>
</select>
```

只进入第一个满足条件的 `<when>`；如果都不满足，进入 `<otherwise>`。这与多个 `<if>` 可以同时拼接不同——`choose` 是互斥的。

**③ `<foreach>`：遍历集合（IN 条件 / 批量插入）**

```xml
<!-- IN 查询 -->
<select id="findUsersByIds" parameterType="list" resultType="User">
    SELECT * FROM users
    WHERE id IN
    <foreach collection="list" item="id"
             open="(" separator="," close=")">
        #{id}
    </foreach>
</select>
```

`collection="list"` 对应 List 类型参数；`open="("` 和 `close=")"` 包裹整个列表；`separator=","` 在元素之间加逗号。如果传入的是数组，`collection` 应写 `"array"`；如果是 Map 中的某个 key，则写该 key 名。

**④ `<set>`：安全更新（自动处理逗号）**

```xml
<update id="updateUserSelective" parameterType="User">
    UPDATE users
    <set>
        <if test="name != null">name = #{name},</if>
        <if test="email != null">email = #{email},</if>
        <if test="age != null">age = #{age},</if>
    </set>
    WHERE id = #{id}
</update>
```

`<set>` 会自动去掉最后一个多余的逗号，避免 `UPDATE ... SET name=?, email=?, WHERE ...` 这类语法错误。

## 🔄 两级缓存

**一级缓存**（`SqlSession` 级别，默认开启）—— 同一个 `SqlSession` 内相同查询走缓存：

```java
try (SqlSession session = factory.openSession()) {
    UserMapper mapper = session.getMapper(UserMapper.class);

    User u1 = mapper.getUserById(1);  // 第 1 次：查数据库
    User u2 = mapper.getUserById(1);  // 第 2 次：直接命中一级缓存

    System.out.println(u1 == u2);  // true（同一对象引用，视实现而定）
}
```

一级缓存不能跨 `SqlSession`，执行 INSERT/UPDATE/DELETE、调用 `clearCache()` 或关闭 Session 都会清空。

**二级缓存**（Mapper/Namespace 级别，需手动开启）—— 跨 `SqlSession` 共享：

① 全局开关（`mybatis-config.xml`）

```xml
<settings>
    <setting name="cacheEnabled" value="true"/>
</settings>
```

② Mapper 中声明 `<cache/>`

```xml
<mapper namespace="com.example.mapper.UserMapper">
    <cache eviction="LRU"
           flushInterval="3600000"
           size="1000"/>
    <!-- select/insert/update/delete ... -->
</mapper>
```

③ 实体类必须可序列化

```java
public class User implements Serializable {
    private static final long serialVersionUID = 1L;
    // ...
}
```

④ 跨 Session 验证

```java
// Session 1
try (SqlSession s1 = factory.openSession()) {
    s1.getMapper(UserMapper.class).getUserById(1);  // 查库，结果入二级缓存
}

// Session 2（不同的 SqlSession）
try (SqlSession s2 = factory.openSession()) {
    s2.getMapper(UserMapper.class).getUserById(1);  // 命中二级缓存，不查库
}
```

`<cache/>` 的 `eviction` 可选 `LRU`（默认）、`FIFO`、`SOFT`、`WEAK`；`flushInterval` 是自动刷新间隔（毫秒）。执行增删改会清空当前 namespace 的二级缓存，因此二级缓存更适合读多写少的数据。

## 🔌 TypeHandler（自定义类型处理器）

当数据库类型与 Java 类型之间的默认转换规则不满足需求时（例如把 JSON 字符串映射为 Java 对象），可以自定义 `TypeHandler`。

**① 继承 `BaseTypeHandler<T>`**（比直接实现接口更简洁）

```java
@MappedTypes(JsonUser.class)          // 声明处理的 Java 类型
@MappedJdbcTypes(JdbcType.VARCHAR)    // 声明对应的 JDBC 类型
public class JsonUserTypeHandler extends BaseTypeHandler<JsonUser> {

    private final ObjectMapper objectMapper = new ObjectMapper();

    // Java 类型 → 数据库类型（写入）
    @Override
    public void setNonNullParameter(PreparedStatement ps, int i,
                                    JsonUser parameter,
                                    JdbcType jdbcType) throws SQLException {
        ps.setString(i, objectMapper.writeValueAsString(parameter));
    }

    // 数据库类型 → Java 类型（读取，按列名）
    @Override
    public JsonUser getNullableResult(ResultSet rs, String columnName)
            throws SQLException {
        String json = rs.getString(columnName);
        return json == null ? null : objectMapper.readValue(json, JsonUser.class);
    }

    // 读取（按列索引）
    @Override
    public JsonUser getNullableResult(ResultSet rs, int columnIndex)
            throws SQLException {
        String json = rs.getString(columnIndex);
        return json == null ? null : objectMapper.readValue(json, JsonUser.class);
    }

    // 读取（CallableStatement，存储过程场景）
    @Override
    public JsonUser getNullableResult(CallableStatement cs, int columnIndex)
            throws SQLException {
        String json = cs.getString(columnIndex);
        return json == null ? null : objectMapper.readValue(json, JsonUser.class);
    }
}
```

**② 注册**（`mybatis-config.xml`）

```xml
<typeHandlers>
    <typeHandler handler="com.example.typehandler.JsonUserTypeHandler"/>
</typeHandlers>
```

**③ 在映射中使用**（可全局生效，也可显式指定）

```xml
<resultMap id="userResultMap" type="User">
    <result property="profile" column="profile_json"
            typeHandler="com.example.typehandler.JsonUserTypeHandler"/>
</resultMap>
```

`BaseTypeHandler` 已经处理了 null 值的情况，四个方法分别覆盖写入和三种读取场景（按列名、按索引、存储过程）。使用 `@MappedTypes`/`@MappedJdbcTypes` 后，满足类型匹配的字段会自动应用该处理器，无需在每个 `<result>` 上重复书写。

## 🧵 其他重要机制

### Executor（执行器）

`SqlSession` 本身不直接执行 SQL，而是委托给 `Executor`。可以通过 `openSession(ExecutorType.XXX)` 切换执行器类型。

```java
// SIMPLE（默认）：每次执行都创建并关闭 Statement
SqlSession simple = factory.openSession(ExecutorType.SIMPLE);

// REUSE：重用 Statement（同一个 SQL 只创建一次）
SqlSession reuse = factory.openSession(ExecutorType.REUSE);

// BATCH：批量执行，适合大量 INSERT/UPDATE
SqlSession batch = factory.openSession(ExecutorType.BATCH);

try (batch) {
    UserMapper mapper = batch.getMapper(UserMapper.class);
    for (User user : userList) {
        mapper.insertUser(user);   // 暂存到批处理
    }
    batch.commit();                // 统一刷入数据库
}
```

`SIMPLE` 是默认执行器，每次执行 SQL 都"创建—执行—关闭" Statement；`REUSE` 会缓存 Statement 以供相同 SQL 重用；`BATCH` 将多条 DML 攒批后统一提交，显著减少网络往返。

### 插件（Interceptor）

插件基于**动态代理 + 责任链**拦截 MyBatis 核心对象的执行。以下是一个统计 SQL 执行耗时的拦截器：

```java
@Intercepts({
    @Signature(
        type = Executor.class,
        method = "query",
        args = {MappedStatement.class, Object.class,
                RowBounds.class, ResultHandler.class}
    )
})
public class SqlTimeInterceptor implements Interceptor {

    @Override
    public Object intercept(Invocation invocation) throws Throwable {
        long start = System.currentTimeMillis();
        try {
            return invocation.proceed();   // 放行，执行原始逻辑
        } finally {
            long cost = System.currentTimeMillis() - start;
            MappedStatement ms =
                (MappedStatement) invocation.getArgs()[0];
            System.out.println("[SQL 耗时] " + ms.getId() + " → " + cost + "ms");
        }
    }
}
```

`@Intercepts` + `@Signature` 精确声明要拦截的类、方法、参数类型；`invocation.proceed()` 调用原始方法。可拦截的四大对象：`Executor`、`StatementHandler`、`ParameterHandler`、`ResultSetHandler`。

### 延迟加载（Lazy Loading）

在一对多/多对一关联中，延迟加载让关联对象在首次被访问时才执行查询，避免一次性加载大量无用数据。

**① 全局开启**

```xml
<settings>
    <setting name="lazyLoadingEnabled" value="true"/>
    <setting name="aggressiveLazyLoading" value="false"/>
    <!-- false：按需加载每个属性；true：访问任一属性即加载全部 -->
</settings>
```

**② 关联映射中指定 `fetchType="lazy"`**

```xml
<resultMap id="userWithOrdersMap" type="User">
    <id property="id" column="id"/>
    <result property="name" column="name"/>

    <collection property="orders"
                column="id"
                ofType="Order"
                select="com.example.mapper.OrderMapper.findByUserId"
                fetchType="lazy"/>
</resultMap>
```

**③ 效果验证**

```java
User user = userMapper.getUserById(1);
// 此时只执行了查 User 的 SQL，orders 尚未加载

System.out.println(user.getName());   // 不触发 orders 查询
List<Order> orders = user.getOrders();
// 首次访问 orders 时，才执行 select="..." 指定的关联查询
```

`fetchType="lazy"` 的优先级高于全局 `lazyLoadingEnabled`，即使全局关闭了延迟加载，标注了 `lazy` 的关联仍然按需加载。
